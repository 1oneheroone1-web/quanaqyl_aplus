# QuanAQYL A+ Learning Portal

Учебный кабинет по физике на русском, казахском и английском. Эта версия предназначена для **Next.js на Vercel с PostgreSQL**. Репозиторий: [1oneheroone1-web/quanaqyl_aplus](https://github.com/1oneheroone1-web/quanaqyl_aplus).

## Возможности

- Главная страница, диагностика, 36 задач, подсказки и разбор решений, учебный маршрут.
- Physics Hub: теория и симуляция движения, выбор 7–12 класса, 36 глав с 40 учебными материалами.
- Прогресс, календарь, история попыток, однократные награды, пауза занятий.
- Магазин Kyōmei: 60 виртуальных товаров, покупки за учебные баллы и коллекция.
- Pomodoro: рабочие интервалы, паузы, сохранение таймера и статистика.
- Регистрация и вход по email и паролю, отдельные профили, приватные фотографии.

React 19, Next.js 16, TypeScript, Tailwind CSS 4. База — PostgreSQL; для быстрого запуска подходит Neon Free из Vercel Marketplace. Авторизация — Better Auth с серверными сессиями. Фото до 2 МиБ хранятся в PostgreSQL и выдаются только вошедшему владельцу через API. Отдельный R2 или Blob не требуется.

## Публикация на Vercel

1. Войдите в свой Vercel и импортируйте этот GitHub-репозиторий. Framework — **Next.js**, Root Directory — корень репозитория, Node.js — **22.x**.
2. Подключите к проекту **Neon** через [Vercel Marketplace](https://vercel.com/marketplace/neon). Выберите тариф **Free** и подходящий регион. Интеграция добавит `DATABASE_URL`; используйте pooled connection string. Если проект уже создан, подключение доступно в его разделе Storage / Marketplace.
3. В Settings → Environment Variables добавьте `BETTER_AUTH_SECRET`: случайный секрет длиной минимум 32 символа. Например, сгенерируйте на рабочей машине командой `openssl rand -base64 32`. Сохраните значение только в настройках окружения.
4. Для окружения **Production** можно добавить `BETTER_AUTH_URL` — полный HTTPS-адрес сайта без пути, например `https://YOUR-PROJECT.vercel.app`. Для собственного домена используйте его. Если переменная отсутствует, приложение автоматически выбирает постоянный Production-домен из `VERCEL_PROJECT_PRODUCTION_URL`, затем адрес текущего deployment из `VERCEL_URL`. Вход и API принимают также точные адреса текущего deployment и ветки из системных переменных Vercel. После выбора собственного домена задайте его явно.
5. Убедитесь, что база и переменные доступны в **Production**. Для **Preview** используйте отдельную тестовую базу и секрет; `BETTER_AUTH_URL` оставьте незаданной, чтобы вход использовал адрес конкретного preview deployment. Preview автоматически разрешает только свои deployment / branch адреса; постоянный Production-домен туда не добавляется. В Vercel должен быть включён доступ к System Environment Variables.
6. Запустите Deploy / Redeploy. `vercel.json` фиксирует pnpm 11.25.0. Сборка выполняет `pnpm run vercel-build`: сначала применяет идемпотентную схему из `db/auth.sql` и `db/postgres.sql`, затем запускает `next build`.
7. Откройте сайт, зарегистрируйте аккаунт, заполните профиль и обновите страницу. Проверьте сохранение попытки, таймера и фотографии.

Если первый deploy был запущен до подключения Neon, подключите базу, добавьте секрет и выполните Redeploy. Ошибка `DATABASE_URL is not configured` означает, что база не подключена к выбранному окружению.

Если при входе возникает `INVALID_ORIGIN`, убедитесь, что открыта актуальная версия проекта. После изменения переменных нужен новый Redeploy; старые deployment-ссылки сохраняют прежние настройки. Для дополнительного собственного домена укажите его точный origin в `BETTER_AUTH_URL` для соответствующего окружения. Домены берутся только из настроек приложения и Vercel, без доверия произвольному заголовку Host или всем сайтам `*.vercel.app`. На разных адресах cookies изолированы, поэтому при переходе с deployment-ссылки на постоянный домен потребуется повторный вход.

Бесплатный план имеет лимиты. Актуальные условия: [Neon](https://neon.com/pricing), [Vercel](https://vercel.com/pricing). Сама загрузка кода не создаёт платные ресурсы.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Серверная строка подключения к PostgreSQL. Для Neon оставьте параметры SSL из выданного URL. |
| `BETTER_AUTH_SECRET` | Случайный секрет авторизации, минимум 32 символа. |
| `BETTER_AUTH_URL` | Необязательный на Vercel публичный origin сайта: HTTPS на production, `http://localhost:3000` для разработки. Имеет приоритет перед автоматическим выбором домена. |

Шаблон — `.env.example`. Рабочие значения храните в `.env.local` или Vercel. У этих переменных нет префикса `NEXT_PUBLIC_`; они не должны попадать в клиентский код или Git.

## Разработка и проверки

Нужны Node.js 22.13+ в ветке 22, pnpm 11.25.0 и PostgreSQL. Для этой рабочей сессии сборки, установка зависимостей и тесты выполняются на `eth-lab`; локальная папка остаётся источником изменений.

```bash
pnpm install --frozen-lockfile
# Создайте .env.local по шаблону и укажите тестовую базу и секрет.
pnpm run db:migrate
pnpm run dev
```

Приложение открывается на `http://localhost:3000`. Для production-сборки и запуска:

```bash
pnpm run build
pnpm run start
```

Проверки:

```bash
pnpm run check
pnpm run check:postgres
pnpm run typecheck
pnpm run lint
pnpm run build
```

`check` проверяет разрешённые домены авторизации и четыре исходные регрессии: учебная логика и переводы, рендер Physics Hub, магазин, Pomodoro. Отдельная проверка доменов — `pnpm run check:auth-origins`. `check:postgres` проверяет реальный PostgreSQL в отдельной временной схеме, включая параллельные покупки и транзакции. Используйте для него тестовую базу. Схемы приложения не удаляются; скрипт очищает только собственную временную схему.

## Хранение и авторизация

Данные сохраняются на сервере и разделяются по ID пользователя из проверенной сессии. Заголовки `oai-authenticated-user-*` больше не задают личность. Пароли обрабатывает Better Auth; серверные сессии сохраняются в базе и действуют фиксированные 7 дней, после чего нужен повторный вход. Выход отзывает сессию сразу. Лимитер авторизации также использует PostgreSQL, чтобы работать между экземплярами Vercel.

Учебные записи и фотографии хранятся в одной базе. Запись попытки с наградой и таймера с историей выполняется транзакционно. PostgreSQL-адаптер сохраняет формат существующего API, использует сериализуемые транзакции и ограниченные повторы конфликтующих записей. Дата и длительность в миллисекундах хранятся в BIGINT.

Подтверждение владения email, отправка писем и самостоятельный сброс пароля пока не подключены. Регистрация использует email как логин. Телефон — необязательное поле профиля, SMS-вход отсутствует. Магазин виртуальный: платежей, доставки и обмена баллов на деньги нет. Ответы присутствуют в учебном каталоге: портал не предназначен для защищённого экзамена.
