# QuanAQYL A+ Learning Portal

Учебный кабинет по физике на русском, казахском и английском. Создан на основе доступного кода `aibekrakhym07-web/quanaqul`; новая версия имеет отдельное размещение и новую базу. Данные прежнего размещения не переносились.

Текущий репозиторий: [1oneheroone1-web/quanaqyl_aplus](https://github.com/1oneheroone1-web/quanaqyl_aplus). Исходники импортированы из архива от 22 октября 2026 года (исходный коммит `e025e902291f3949580f18e393dcd4c9d8549792`). Архив не содержит пользовательскую базу, фотографии и секреты.

Текущая сборка использует Vinext/Vite и Cloudflare Workers, D1 и R2. Для Vercel необходим перенос серверной среды, постоянного хранения и авторизации Sites; одного подключения репозитория к Vercel недостаточно. Инструкции ниже описывают исходную версию для Sites.

## Что работает

- Адаптивная главная: следующий шаг, реальные результаты, активность за 7 дней, серия занятий, цель.
- Диагностика по выбранному уровню и темам. Подсказки и разбор доступны только после завершения диагностической сессии.
- 36 задач: 28 базовых по 14 темам и 8 многошаговых задач уровня A-level. Числовые ответы, десятичная запятая, научная запись, подсказки и пошаговые решения.
- Учебный маршрут: сначала темы с последними результатами ниже 80%, затем непроверенные темы, затем повторение. Учитывается выбранный класс или уровень. Для каждой задачи используется последняя попытка.
- Магазин Kyōmei: 60 виртуальных товаров из предоставленных архивов, цены 15–90 共, категории, поиск и покупка 1–10 штук. Баланс, покупки и коллекция в профиле сохраняются на сервере.
- Physics Learning Hub: вкладки «Теория» и «Физика в действии». Выбор 7–12 класса, 36 раскрывающихся глав с 40 материалами для 9–12, честные пустые состояния для 7–8. Прежняя симуляция движения сохранена.
- Прогресс, календарь, история попыток, однократные учебные награды и пауза занятий.
- Профиль: фото, имя, школа/университет, класс/курс, город, цели, интересы, биография, телефон и часы занятий.
- Вход через ChatGPT на Sites. Сервер получает проверенную платформой идентичность. Профиль и результаты привязаны к ID пользователя; фото доступны через авторизованный API.
- D1 хранит профиль, попытки и награды; R2 хранит фотографии. Локально в браузере сохраняется только предпочтение языка.

## Честные границы первой версии

План является рекомендательной системой по правилам, а не подключённой языковой моделью. LLM-ментор, Google OAuth и SMS-регистрация не подключены. Телефон — необязательное неподтверждённое поле профиля.

Диагностика — краткая формирующая проверка, не стандартизированный экзамен. Банк задач не покрывает полный университетский курс. Ответы присутствуют в клиентском учебном каталоге: сайт не предназначен для защищённого экзамена. История API ограничена 500 последними попытками; сводные показатели рассчитаны по этой истории.

## Оформление по референсам

Нежная голубая палитра, градиентная шапка, белые карточки с крупным скруглением, иллюстрации планеты и гор. Оформление объединяет главную, диагностику, учебный план, награды, профиль, задачи и прогресс.

Диагностика показывает темы выбранного класса, выбор уровня сделан доступной с клавиатуры группой переключателей. В учебном плане и диагностике используются одинаковые цветные значки и описания тем (`components/topic-style.tsx`). Награды представлены карточками показателей, кошельком Kyōmei и объяснением начисления. Источники показателей — сохранённые результаты пользователя.

## Магазин Kyōmei

В боковом меню «Магазин Kyōmei» доступны 30 сладостей и 30 канцелярских товаров. Это виртуальная коллекция: доставки, денежных платежей и обмена баллов на деньги нет. Оригинальные иллюстрации из архивов `KYOMI_SHOP_30_JAPANESE_SWEETS.zip` и `KYOMI_SHOP_30_JAPANESE_STATIONERY.zip` являются AI-концептами. Они не подтверждают вид реальных упаковок или наличие физических товаров.

Каталог находится в `lib/shop-products.json`: стабильный ID, название, категория, цена, изображение и описание EN/RU/KK. Изначальный банк задач позволяет заработать до 2600 共; один экземпляр каждого товара стоит суммарно 2315 共. Повторные покупки доступны, но не дают дополнительных учебных баллов.

`lib/shop-server.ts` проверяет покупку и списывает средства одной условной SQL-вставкой. Цена определяется на сервере; количество ограничено 1–10. Баланс — сумма учебных наград минус сумма покупок. Сами награды не изменяются. Ключ пользователя и ID запроса не допускают повторного списания при повторной отправке. Одновременные запросы проверяют доступные средства в момент записи. Данные одного пользователя недоступны другому.

`app/api/shop/route.ts` использует существующий вход и защиту запросов. `GET` возвращает баланс, количество каждого товара и 20 последних покупок; `POST` принимает `{requestId, productId, quantity}`. Все покупки учитываются в балансе и коллекции независимо от ограничения истории. При сетевой ошибке повторная отправка в том же окне использует тот же ID.

`components/kyomei-shop.tsx` — витрина, фильтры, подтверждение покупки и история. `components/shop-collection.tsx` — коллекция в профиле с количеством каждого товара. `app/shop.css` — адаптивное оформление; `lib/i18n.ts` — интерфейс на трёх языках. Главная и кошелёк показывают доступный остаток; сумма всех заработанных наград показана отдельно.

Для покупок добавлена таблица `shop_purchases` и новая миграция `drizzle/0001_demonic_imperial_guard.sql`. Существующие таблицы и прежняя миграция сохранены. Sites применяет новую миграцию при публикации; локальная база обновляется отдельно.

Проверка `node scripts/check-shop.mjs` запускает настоящую логику покупок и SQL-миграции во временной SQLite-базе: проверяет остаток, количество, недопустимый ввод, нехватку средств, повторные и конкурирующие запросы, разделение пользователей, сохранность после повторного открытия базы и рендер на трёх языках. Она не изменяет реальные аккаунты и не заменяет браузерную проверку взаимодействий.

## Запуск на своём компьютере

Нужен Node.js 22.13+ и pnpm из `package.json`.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm run build
```

При первом запуске локальной базы применить начальную миграцию **один раз**:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_useful_talisman.sql
```

Для новой локальной базы также применить миграцию магазина. Для уже существующей базы с применённой `0000` выполнить только эту новую миграцию, один раз:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_demonic_imperial_guard.sql
```

Для таймера применить новую миграцию один раз после предыдущих:

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_rainy_blue_marvel.sql
```

Затем:

```bash
pnpm run dev
```

Открыть адрес из терминала (обычно `http://localhost:5173`). На обычном локальном компьютере встроенная разработческая имитация входа создаёт тестовую личность, без настоящего ChatGPT OAuth. Она ограничена loopback-соединениями и не включена в production-сборку. Локальное состояние лежит в `.wrangler/state`.

В управляемой среде Sites используется её штатный запуск и реальная идентичность платформы. Самостоятельное размещение на другом хостинге потребует собственного надёжного OAuth-сеанса и проверки личности: входящие `oai-authenticated-user-*` заголовки можно доверять только за проверенным диспетчером Sites. Не открывать Worker в обход этого диспетчера.

Проверка данных включает 36 модулей, 40 ресурсов, 28 уникальных URL, правильные роли четырёх дополнительных видео, оригинальные поля, стабильные ID и три языка. Серверный рендер проверяет все раскрытые главы на EN/RU/KK, шесть переключателей классов, пустые состояния 7–8, ссылки и наличие слота симуляции. Это не браузерный тест взаимодействий и размеров экрана.

Локально пройти пользовательский сценарий:

1. Войти и сохранить имя, уровень, цель и фото. Обновить страницу, проверить сохранение.
2. Пройти диагностику минимум по двум темам, допустив одну ошибку. До завершения не должно быть подсказок и решений.
3. Открыть план: ошибочная тема должна оказаться первой. Решить обе задачи этой темы и проверить обновление прогресса.
4. Повторить успешно решённый блок: награда не должна начислиться ещё раз.
5. Проверить русский, казахский и английский; профиль и упражнения на узком экране.
6. Открыть «Физика»: сначала должна появиться теория. Выбрать 7 и 8 классы: увидеть сообщение «Скоро» и кнопку перехода к модели.
7. Для 9–12 классов раскрыть главы. Проверить основные материалы и четыре дополнительных видео, открытие новой вкладки, клавиатурное управление Tab/Enter/стрелками.
8. Переключить EN/RU/KK при раскрытой главе: класс и глава сохраняются, подписи переводятся, официальные названия ресурсов остаются исходными.
9. Во вкладке «Физика в действии» при начальных значениях v₀=4, a=2, t=5 получить x=45 м и v=14 м/с. Изменить параметры, переключить вкладки и вернуться: значения сохраняются. Проверить сброс.
10. Проверить ширины 360, 768 и 1440 пикселей: горизонтальная прокрутка допустима только внутри переключателя классов, не у всей страницы. Карточки и кнопки должны помещаться.

Для предыдущих разделов выполнены автоматические проверки; полный браузерный сценарий с реальным входом и экспериментальный WebMCP отдельно не проверены. Типизация не заменяет эту финальную ручную проверку. Проверки нового таймера описаны ниже.

## Pomodoro: работа, отдых и прогресс

После входа на всех страницах доступна плавающая карточка Pomodoro. Задайте время работы (1–120 целых минут) и отдыха (1–60), нажмите «Начать». Карточку можно перемещать за значок слева в заголовке мышью, касанием или стрелками клавиатуры; сворачивание сохраняет работающий таймер. Доступны пауза, продолжение и завершение со сбросом. После работы автоматически начинается отдых; после отдыха таймер ждёт нового запуска.

Состояние хранится в `focus_timers`, законченные и прерванные рабочие сеансы — в `focus_sessions`, отдельно для каждого пользователя. Время рассчитывается сервером. Пауза и отдых исключены из времени работы. После перезагрузки таймер восстанавливается; если браузер был закрыт, при следующем открытии учитывается исходный срок окончания. Новые рабочие циклы самостоятельно не запускаются. Место карточки хранится только в браузере. Kyōmei за таймер не начисляются.

В разделе «Прогресс» показаны данные за последние семь календарных дней в часовом поясе устройства:

- **Время фокуса:** сумма рабочего времени законченных и прерванных сеансов, без активного сеанса, отдыха и пауз.
- **Завершённость:** число полностью выполненных рабочих сеансов / все законченные рабочие сеансы × 100%.
- **Активные дни**, столбчатый график минут по дням, два наблюдения и одна рекомендация. Сеанс относится к дате его окончания. При отсутствии данных показывается пустое состояние; результаты не выдумываются.

Рекомендация вычисляется простыми правилами: при трёх и более сеансах и завершённости ниже 60% — сократить рабочий интервал; при менее чем четырёх активных днях — добавить один день занятий; иначе — сохранить ритм. Это объяснимая логика, а не ответ LLM и не доказательство улучшения знаний по физике. История показывает до 20 последних сеансов за эти семь дней.

### Проверка и демонстрация

`node scripts/check-focus.mjs` проверяет старт, паузу, продолжение, автоматический отдых, сброс, исключение пауз, повторные и конкурирующие запросы, разделение пользователей, сохранность после повторного открытия базы, формулы метрик и рендер на трёх языках. Браузерная проверка компонентов выполнена на широком экране и в области шириной 390 px: ввод, ошибка при нуле, старт, пауза, сворачивание, перемещение и переводы. Использовались изолированные временные тестовые данные; тестовые страницы удалены из публикации. Полный сценарий с реальной авторизацией в браузере ещё требует ручной проверки.

Для защиты проекта поставьте 1 минуту работы и 1 минуту отдыха. Покажите перемещение и паузу, затем продолжите и дождитесь отдыха. Откройте «Прогресс», объясните формулы и график. Обновите страницу, чтобы показать сохранение. Попробуйте ввести 0 минут: появится сообщение об ошибке. Подготовьте реальные сеансы заранее, чтобы график отражал несколько дней.

Два конкретных риска: чтение чужих сеансов и подделка длительности. API берёт пользователя из существующей проверенной авторизации; пользователь, даты и готовая длительность не принимаются из тела запроса. Сервер ограничивает интервалы, проверяет версию состояния и сохраняет историю вместе с таймером одной транзакцией. Следующее улучшение — ограничение частоты запросов на пользователя; сейчас специальный rate limit для этого API не добавлен. Сам таймер измеряет прошедшее рабочее время, но не подтверждает, что ученик действительно решал задачи.

## GitHub: как отправить изменения

Для дальнейших изменений клонируйте текущий репозиторий и создайте ветку:

```bash
git clone https://github.com/1oneheroone1-web/quanaqyl_aplus.git
cd quanaqyl_aplus
git switch -c your-change
```

Перед отправкой проверьте изменения. `.openai/hosting.json` привязан к исходному размещению Sites: для другого сайта нужны собственные настройки. Секреты и локальные базы не добавляйте в Git. Если используется удалённая рабочая машина, следующие проверки запускайте в её копии проекта:

```bash
node scripts/check-learning.mjs
node scripts/check-physics-hub.mjs
pnpm exec tsc --noEmit
pnpm run build
node scripts/check-shop.mjs
node scripts/check-focus.mjs
```

Затем на локальном компьютере добавьте нужные файлы, создайте коммит и отправьте ветку. Откройте Pull Request в `main`. Загрузка исходников в GitHub сама по себе не публикует сайт; размещение и серверные службы настраиваются отдельно.

## Что дальше для конкурсной версии

Подключить настоящий LLM-ментор через серверный API с ограничениями расходов, расширить банк задач и провести пилот: диагностика до обучения → занятия → повторная проверка новыми задачами. Сравнивать результаты только с учётом размера выборки и одинаковых условий. Это позволит показать измеримый учебный эффект.
